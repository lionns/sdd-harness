# Data Model

The harness has four record types. All are files; the filesystem is the whole store.

## Task — `docs/tasks/<ID>-<slug>.md`

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `id` | string | yes | `T-###`. The filename must start with it. |
| `title` | string | yes | Short. |
| `status` | enum | yes | `ready` `doing` `review` `blocked` `done` `superseded`. The only place state lives. |
| `profile` | enum | yes | `solo` or `team`. |
| `harness` | string | yes | Must appear as a `### x.y.z` heading in `docs/sdd/VERSION.md`. |
| `role` | string | no | From `docs/sdd/ROLES.md`. |
| `goal` | string | yes | One or two sentences. Rendered into `STATUS.md`. |
| `decisions` | list | no | `D-###` ids; each must have a file. |

Body sections: Sources, Scope, Out of Scope, Acceptance Criteria, Verification, Assumptions, Risks,
Outcome, Review, Trace, and — under `team` — Validation. Budget: 120 lines, trace block 25.

## Decision — `docs/decisions/D-###-<slug>.md`

`id` from the filename · `Status: proposed | accepted | superseded` · `Date` · `Supersedes` ·
`Tasks`. The `# D-### — Title` heading must start with the id. Budget: 40 lines. Immutable once
accepted: supersede with a new file rather than editing. Indexed by a generated `README.md`.

## Journal line — `JOURNAL.md`

Exactly seven pipe-separated fields, append-only, newest last:

`date | task-id | state | outcome | N files | checks result | decisions`

Fields 1-3 are validated (`YYYY-MM-DD`, `T-###`, a task state); the rest are free-form, `-` when
empty. Every `done` task must have a line carrying its id.

## Trace

Under `solo`, a `## Trace` section inside the task file. Under `team`, a file at
`docs/traces/<YYYY-MM-DD>_<task-id>_<role>.md`. Same shape, same 25-line budget, one sub-entry per
working round; compress older rounds when the budget fills.

## Lifecycle

Records are created by hand from `docs/sdd/TEMPLATES.md` and never deleted. A task ends `done` or
`superseded`; a decision ends `accepted` or `superseded`. History belongs to `git log --follow`, not
to appended sections — task sections are overwritten in place.

## Derived Files

`STATUS.md` and `docs/decisions/README.md` are pure functions of the above. They hold no state, are
regenerated by `scripts/harness-status.mjs`, and are never hand-edited.
